# 유지케어 병원 대시보드 (원장님용)

환자 앱(레포 루트)과 짝을 이루는 **병원용 웹 화면** 목업이에요. 빌드 없이 `index.html`을 브라우저로 열면 바로 동작해요.

## 화면

| 메뉴 | 하는 일 |
| --- | --- |
| 진료실 | 왼쪽: 확인 필요 환자 + 오늘 진료 순서(진료 전 기록 여부, 남긴 질문 수). 오른쪽: 환자 차트 — 진료 전 기록 상태(체중 측정·기본 문진 생략 가능), 앱 기록 자동 입력(체중·식욕·스트레스·수면·증상·식욕 SOS), **이번 진료에서 확인할 것** 자동 정리, **진료 기록**(처방·답변·조언·다음 예약 상용구를 눌러 자동 입력, 답변·조언·다음 예약은 환자 앱으로 전송), 차트 타임라인, 내원 요청 |
| 문의함 | 환자가 진료 사이에 남긴 질문만 모아보기 (답변 대기 / 다음 진료 때 / 답변 완료). 상용구로 답하면 환자 앱과 차트에 함께 남아요 |
| 내원 일정 | 점검 내원 시기 환자에게 요청, 환자 선택 대기, 이번 주 예약·빈 시간 |
| 환자 초대 | QR·링크·문자, 첫 진료 때 안내 멘트, 초대 현황 |
| 진료 효율 | 문진·체중 측정 시간, 진료 전 기록률, 전화 문의 감소, 차트 작성 시간, 하루 진료 가능 인원 (예시 데이터) |
| 설정 | 상용구 관리(분류별 켜기/끄기·추가), 환자 앱 기록 항목, "확인할 것" 기준, 이용 요금, EMR·처방·서류·예약 연동 로드맵 |

## 환자 앱과 맞춘 값

- 데모 환자 이지은: 체중 72.6kg(유지 범위 68–72 초과), 식욕 7일 평균 8.2, 수면 5시간, 2주간 +2.4kg — `src/data/mock.ts`의 `risk` 시나리오와 같음
- 내원 요청 메시지: "걱정할 단계는 아니에요. 지금 잡으면 충분히 돌아갈 수 있으니 이번 주에 한번 들러 주세요."
- 메모 태그는 환자 앱 홈의 원장님 메모 카드에 문장으로 보여주는 것을 전제로 해요 (태그 → 문장 매핑은 `index.html`의 `TAGS`)

## 환자 앱과 실시간 연동

레포 루트에서 `npm run dev`를 켜고 두 화면을 같은 주소에서 열면, 탭 사이로 데이터가 실시간으로 오가요. (서버 없이 같은 출처의 `localStorage`와 `storage` 이벤트 사용, 키: `keepfit-link`)

- 환자 앱: http://localhost:5173/app/
- 병원 대시보드: http://localhost:5173/clinic-dashboard/ (사이드바에 "환자 앱 연결됨" 표시)

| 환자 앱에서 | 대시보드에서 |
| --- | --- |
| 30초 기록 또는 AI 전화를 마침 | 이지은 카드·기록 목록이 그 값으로 바뀌고 알림이 떠요. 위험이면 "확인 필요"로 올라와요 |
| 식욕 SOS를 씀 | 이지은 카드의 식욕 SOS 횟수와 방금 쓴 SOS(점수·이유·결과)가 바뀌고 알림이 떠요 |
| | 내원 요청 + 진료 가능 시간 선택 → 환자 앱 홈에 배너, 알림 화면에 **원장님이 고른 시간만** 보여요 |
| 시간 골라 예약 | "내원 예약 확정"으로 바로 바뀌고 알림이 떠요. 내원 일정에도 들어가요 |
| | 메모 보내기 → 환자 앱 홈 맨 위에 "새 메모"로 떠요 |
| 메모에서 **확인했어요** | 마지막 메모 옆에 "환자가 읽음"으로 바뀌고 알림이 떠요 |
| 데모 "처음부터" | 이지은의 요청·예약·메모가 지워지고 정상 상태로 돌아가요 |
| | 설정 → **데모 초기화**도 요청·예약·메모를 지워요 (환자 앱 알림도 함께 사라짐) |

연동되는 환자는 데모 환자 **이지은** 한 명이에요. 나머지 환자는 예시 데이터예요.

## 데모 동작

- 환자 앱 탭이 열려 있지 않으면(또는 `index.html`을 파일로 바로 열면) 예전처럼 내원 요청 약 6초 뒤 환자가 첫 번째 제안 시간으로 예약한 것처럼 바뀌어요.
- 대시보드 화면 상태는 새로고침하면 처음으로 돌아가요. 이지은의 요청·예약·메모는 연동 기록에서 다시 불러와요.
